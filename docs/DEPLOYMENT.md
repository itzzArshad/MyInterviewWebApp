# Deploying to learn.arshadarif.in (all free tiers)

```
 iPhone / laptop ──HTTPS──▶ learn.arshadarif.in (Vercel, Next.js)
                                   │  /api/* proxied (same origin → cookies work on iOS)
                                   ▼
                     academy-api.onrender.com (Render free, Docker, Spring Boot)
                          │                         │
                          ▼                         ▼
                Neon PostgreSQL (free)     GitHub: itzzArshad/academy-content (private)
                  progress, quizzes,         every lesson as a .md file, versioned
                  lessons (read copy)
```

Your portfolio at `arshadarif.in` is not touched — this is a separate Vercel project on a subdomain.
Do the steps in order; each takes a few minutes. Secrets go **only** into the Render/Vercel dashboards
(and your local `backend/.env.local`), never into git.

---

## 1. Lesson repo + token (GitHub)

1. Create a **private** repository named `academy-content` — tick **Add a README** so the `main` branch exists.
2. Create a token: GitHub → Settings → Developer settings → **Fine-grained personal access tokens** → Generate new token
   - Resource owner: `itzzArshad` · Expiration: up to 1 year (set yourself a renewal reminder)
   - Repository access: **Only select repositories** → `academy-content`
   - Repository permissions: **Contents → Read and write** (Metadata: read is added automatically)
3. Keep the token for step 3. To test locally too, add to `backend/.env.local`:
   ```properties
   GITHUB_CONTENT_REPO=itzzArshad/academy-content
   GITHUB_CONTENT_TOKEN=github_pat_...
   ```

## 2. Database (Neon)

✅ **Done.** The Neon project (`bold-king-88766073`, branch `production`, AWS Singapore) is linked to this repo
(`neon.ts` + git-ignored `.neon`), and `neon deploy` wrote its connection strings to the git-ignored
repo-root `.env.local`:

| Variable | What it is | Used for |
|---|---|---|
| `DATABASE_URL` | pooled connection (`-pooler` host, PgBouncer) | the app's queries |
| `DATABASE_URL_UNPOOLED` | direct connection | Flyway migrations |

The backend accepts these exactly as Neon writes them (`NeonDatabaseUrlPostProcessor` converts them for JDBC,
adds `prepareThreshold=0` for the pooler, and derives the direct URL if only the pooled one is set).
Tables are created automatically by Flyway on the API's first start.

To get the values for Render: open `.env.local` (or Neon Console → **Connect**, pooled and direct).
Re-pull any time with `neon env pull`. To try the app locally against Neon instead of local PostgreSQL:
`./mvnw spring-boot:run -Dspring-boot.run.profiles=dev,neon` — but prefer a Neon dev branch
(`neon checkout dev --create`) so local experiments never touch `production`.

## 3. API (Render)

1. Sign in at render.com with GitHub → **New → Blueprint** → choose `itzzArshad/MyInterviewWebApp`.
   Render reads [`render.yaml`](../render.yaml) and asks for the secret values:
   - `DATABASE_URL`, `DATABASE_URL_UNPOOLED` — paste the two values from `.env.local` exactly as they are (without the surrounding quotes)
   - `ACADEMY_OWNER_USERNAME`, `ACADEMY_OWNER_PASSWORD`, `ACADEMY_OWNER_DISPLAY_NAME` — your login (use a strong password; it is stored only as a BCrypt hash)
   - `GITHUB_CONTENT_TOKEN` — from step 1
   - `ACADEMY_JWT_SECRET` is generated by Render automatically.
2. **Apply**. The first Docker build takes ~5–10 minutes. Note the service URL, e.g. `https://academy-api.onrender.com`.
3. Check `https://<your-render-url>/actuator/health` returns `{"status":"UP"}`.

## 4. Web app (Vercel)

1. vercel.com → **Add New → Project** → import `itzzArshad/MyInterviewWebApp`.
2. **Root Directory: `frontend`** (framework is detected as Next.js).
3. Environment variable: `BACKEND_URL` = your Render URL from step 3 (no trailing slash) → **Deploy**.
   (If you change `BACKEND_URL` later, redeploy — the `/api` proxy is fixed at build time.)
4. Project → **Settings → Domains** → add `learn.arshadarif.in`. Vercel shows the DNS record to create — usually
   `CNAME learn → cname.vercel-dns.com` (use exactly what it shows).

## 5. DNS (Hostinger)

`arshadarif.in` uses Hostinger's nameservers, so the record is added there:
hPanel → **Domains → arshadarif.in → DNS / Nameservers → Manage DNS records** → add
`Type: CNAME · Name: learn · Points to: <value from Vercel> · TTL: default`.
Within minutes Vercel shows the domain as valid and issues the HTTPS certificate.

## 6. Keep the API awake

GitHub repo `MyInterviewWebApp` → Settings → **Secrets and variables → Actions → Variables** → New variable
`BACKEND_URL` = your Render URL. The [keep-alive workflow](../.github/workflows/keepalive.yml) then pings the
API every 10 minutes so you rarely hit Render's ~50 s cold start.

## 7. First run

1. Open https://learn.arshadarif.in and log in with the owner credentials from step 3.
2. **Settings → Back up all lessons** — commits the 4 bundled lessons into `academy-content`.
3. Write lessons: open any topic → **Copy prompt** → ChatGPT/Claude → paste the answer → **Save lesson**.

## 8. Install as an app

- **iPhone (Safari):** open learn.arshadarif.in → Share → **Add to Home Screen**. It opens full-screen with its own icon.
- **Windows (Edge/Chrome):** the install icon in the address bar → **Install**.

## Free-tier limits worth knowing

| Service | Limit | Effect / mitigation |
|---|---|---|
| Render free | 512 MB RAM; sleeps after 15 min idle; 750 instance-hours/month | Keep-alive ping; JVM tuned for 512 MB in the Dockerfile. One always-on service ≈ 744 h/month fits. |
| Neon free | ~0.5 GB storage; compute auto-suspends when idle | First query after idle takes ~1 s. Text lessons are tiny. |
| Vercel Hobby | Non-commercial use | Personal learning app — fine. |
| GitHub Actions | Scheduled workflows pause after 60 days without repo activity | Re-enable in the Actions tab if the API starts sleeping. |

**What if the database is lost?** Lessons: **Settings → Restore from GitHub** rebuilds them from `academy-content`.
Progress/quiz history live only in Neon — automated nightly database backups are planned for Phase 7.
